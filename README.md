# BookNest

BookNest — веб-читалка для личной библиотеки на FastAPI и React. Книги, главы, закладки и прогресс хранятся в базе данных.

## Возможности

- Импорт TXT, Markdown, EPUB, DOCX и PDF размером до 20 МБ; импорт по прямой ссылке или с HTML-страницы.
- Извлечение метаданных и разбиение книги на главы. Поддержка UTF-8, Windows-1251, KOI8-R и CP866, восстановление некоторых ошибок кодировки старых русских текстов.
- Библиотека с поиском, сортировкой, прогрессом чтения и редактированием названия и автора.
- Оглавление, поиск по книге, закладки и автосохранение позиции.
- Markdown с таблицами, списками, блоками кода и формулами KaTeX (`$...$`, `$$...$$`).
- Пять тем страницы книги, пять вариантов шрифта, настройка размера текста, межстрочного интервала, ширины страницы, отступов абзацев, разрядки и выравнивания.
- Общая палитра книги, библиотеки и интерфейса; системная, светлая и тёмная тема. Стиль интерфейса: Editorial, Glass Cards, Liquid Glass, Minimal.
- Режим фокусировки, полноэкранное чтение, горячие клавиши и мобильная навигация.
- Нейросетевой диктор: шесть голосов, предпрослушивание, скорость 0,7–1,35×, пауза, продолжение и остановка. Подсветка произносимых слов в реальном времени.

## Диктор и подсветка слов

Тема страницы книги применяется и к главному экрану, панелям и экрану загрузки. В светлом режиме доступны «Бумага», «Слоновая кость» и «Сепия», в тёмном — «Ночь» и «Полночь». Для каждого режима запоминается последняя палитра. Системная тема следует настройке устройства. Настройки сохраняются в браузере и в общих предпочтениях на сервере.

Откройте книгу и нажмите кнопку с динамиком. В поле **«Начать чтение»** можно выбрать начало главы или текущее место на странице. Во втором случае диктор начнёт с первого видимого слова в момент запуска.

Для точного выбора нажмите **«Выбрать слово в тексте»**, затем нужное слово в книге. Панель откроется снова и покажет начало выбранного фрагмента; нажмите **«Читать отсюда»**. Слово также можно выбрать клавишами Tab и Enter. Кнопка «Отмена» или Esc возвращает в панель без изменения выбранного места. Диктор читает до конца текущего раздела; для другой главы чтение запускается отдельно.

Ползунок **«Скорость»** меняет темп сразу, включая уже воспроизводимый фрагмент и предпрослушивание. На паузе новая скорость применяется при продолжении. Высота голоса сохраняется, подсветка следует за временем аудио. Скорость сохраняется в браузере.

На телефоне кнопка **«Весь экран»** находится в нижней панели. Повторное нажатие возвращает обычный режим. Если браузер или встроенное окно приложения не поддерживает полноэкранный API, читалка разворачивается в пределах окна и скрывает свои панели; выйти можно кнопкой **«Выйти из полного экрана»**. Панели самого браузера в этом случае остаются. При включении фокусировки настройки закрываются, а кнопка **«Выйти из фокуса»** остаётся видимой, в том числе на узком экране.

В панели диктора есть ползунок-переключатель **«Подсветка слов»**. По умолчанию он включён; выбор сохраняется в браузере. Подсветку можно отключить и снова включить во время воспроизведения или на паузе, без перезапуска аудио. При закрытии панели чтение продолжается. Остановка, завершение чтения, переход к другой главе или выход из читалки убирают выделение.

Backend получает MP3 и временные метки `WordBoundary` из одного потока `edge-tts`. Frontend сверяет метки с текущим временем HTML Audio. Подсветка работает в обычном тексте и Markdown, включая заголовки, ссылки, списки и таблицы. Блоки кода пропускаются, формулы озвучиваются словом «формула». Предпрослушивание голоса не выделяет текст книги. Если сервис не прислал метки слов, аудио воспроизводится без подсветки, а панель сообщает об этом.

Для диктора нужен исходящий доступ backend в интернет. API-ключ не требуется. Озвучиваемый текст отправляется внешнему TTS-сервису Microsoft через `edge-tts`; системные голоса браузера не используются. Голос применяется при новом запуске чтения, его выбор сохраняется в браузере.

## Локальный запуск

Понадобятся Python 3.10+ и Node.js 22.12+ (в Docker используются Python 3.13 и Node.js 22).

Из корня проекта создайте окружение и установите зависимости:

```bash
python -m venv .venv
```

Активируйте его в PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

В Linux/macOS:

```bash
source .venv/bin/activate
```

Запустите backend:

```bash
pip install -r backend/requirements.txt
uvicorn backend.app.main:app --reload --port 8000
```

По умолчанию SQLite создаёт `booknest.db` в рабочей папке запуска. Для PostgreSQL задайте переменную окружения `DATABASE_URL`. Настройки из `.env` нужно передать окружению самостоятельно либо запустить Uvicorn с `--env-file .env`; пример переменных находится в [.env.example](.env.example).

В другом терминале запустите frontend:

```bash
cd frontend
npm install
npm run dev
```

В PowerShell при блокировке `npm.ps1` используйте `npm.cmd` вместо `npm`.

Откройте <http://localhost:5173>. Vite проксирует `/api` на <http://localhost:8000>. Документация API доступна по адресу <http://localhost:8000/docs>.

Для проверки сборки frontend:

```bash
cd frontend
npm run build
```

Проверки диктора и синхронизации подсветки (из корня проекта):

```bash
python -m unittest discover -s backend/tests -v
node --experimental-strip-types --test frontend/tests/speech.test.mjs
node --experimental-strip-types --test frontend/tests/fullscreen.test.mjs
node --experimental-strip-types --test frontend/tests/appearance.test.mjs
```

Тесты backend используют подставной TTS-поток и не обращаются к внешнему сервису. Для тестов frontend нужен Node.js 22.18+.

## Docker

```bash
docker build -t booknest .
docker run --rm -p 10000:10000 -e PORT=10000 booknest
```

Приложение доступно по адресу <http://localhost:10000>. В этом варианте база SQLite находится внутри контейнера. Для сохранения библиотеки между запусками подключите том:

```bash
docker run --rm -p 10000:10000 -v booknest-data:/data -e DATABASE_URL=sqlite:////data/booknest.db booknest
```

Можно передать `DATABASE_URL` с адресом PostgreSQL. Docker собирает frontend, а FastAPI раздаёт готовое приложение и API с одного порта.

## Render

1. Отправьте проект в GitHub/GitLab-репозиторий.
2. В Render выберите **New → Blueprint** и укажите репозиторий с [render.yaml](render.yaml).
3. Blueprint создаст Docker Web Service и PostgreSQL и передаст строку подключения через `DATABASE_URL`.
4. Откройте адрес созданного сервиса. Проверка состояния использует `/api/health`.

В `render.yaml` указан план `free` для обоих ресурсов. Перед развёртыванием проверьте действующие ограничения выбранных тарифов и срок хранения базы. Разобранные книги, прогресс и закладки хранятся в PostgreSQL; исходные загруженные файлы не сохраняются. Локальная SQLite в контейнере без постоянного тома не подходит для хранения библиотеки между пересозданиями сервиса.

## API

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/books` | Список книг |
| `POST /api/books/upload` | Загрузка файла (`multipart/form-data`, поле `file`) |
| `POST /api/books/import-url` | Импорт по ссылке (`{"url":"https://example.org/book.txt"}`) |
| `GET /api/books/{id}` | Книга с главами |
| `PATCH /api/books/{id}` | Изменение названия и автора |
| `DELETE /api/books/{id}` | Удаление книги |
| `PUT /api/books/{id}/progress` | Сохранение главы и позиции прокрутки |
| `GET /api/books/{id}/bookmarks` | Список закладок |
| `POST /api/books/{id}/bookmarks` | Создание закладки |
| `DELETE /api/bookmarks/{id}` | Удаление закладки |
| `GET /api/preferences` | Настройки страницы чтения |
| `PUT /api/preferences` | Сохранение настроек |
| `GET /api/tts/voices` | Доступные голоса диктора |
| `POST /api/tts/speech` | MP3 для предпрослушивания или озвучивания |
| `POST /api/tts/narration` | MP3 в Base64 и временные метки слов для подсветки |
| `GET /api/health` | Проверка состояния |

Оба TTS-метода принимают JSON:

```json
{"text":"Привет, мир!","voice":"ru-RU-SvetlanaNeural","rate":1.0}
```

Лимит текста одного запроса — 3000 символов. Первый фрагмент читалки ограничен 240 символами и готовится при открытии панели диктора. Дальше идут фрагменты до 1250 символов: два следующих синтезируются и загружаются в аудиоплеер заранее, пока диктор читает текущий. Готовое аудио повторно используется при перезапуске; кэш в памяти вкладки ограничен 12 МБ и 16 фрагментами. Остановка отменяет незавершённые запросы. Ответ `/api/tts/narration` содержит `audio` (MP3 в Base64) и `boundaries` (массив объектов с `text`, `start`, `duration`; время в секундах от начала MP3).

Импорт по URL выполняется на backend. Разрешены HTTP/HTTPS, стандартные порты и публичные адреса; размер скачанного файла ограничен 20 МБ.

## Структура проекта

```text
backend/app/
  main.py          # API, импорт по URL и синтез речи
  schemas.py       # Схемы запросов и ответов
  parser.py        # Разбор книг и обработка кодировок
  models.py        # Модели книг, прогресса, закладок и настроек
  database.py      # SQLite / PostgreSQL
frontend/src/
  pages/           # Библиотека и читалка
  components/      # Панели настроек, диктор, Markdown и импорт
  lib/             # API, типы, темы и синхронизация подсветки
Dockerfile
render.yaml
```

Приложение рассчитано на одну общую библиотеку. Авторизация и разделение данных пользователей пока не реализованы. PDF обрабатывается через извлечение текста; OCR для сканов отсутствует.
